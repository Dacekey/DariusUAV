# Log-01: Setup Mono Cam Environment
**Date:** 2026-08-02
**Target:** `gazebosim/custom_world/baylands_x500_mono_cam.sdf`

## I. Yêu cầu của người dùng
*   Nhân bản file world `baylands_x500.sdf` thành `baylands_x500_mono_cam.sdf` và thay thế model drone thành `x500_mono_cam`.
*   Cập nhật các script chạy để cho phép khởi động thông qua cờ `--baylands_x500_mono_cam`.
*   Cập nhật tài liệu `README.md` tương ứng.

## II. Các thay đổi đã thực hiện

### 1. Tạo file World mới
**Trước khi cập nhật:** Chỉ có file `baylands_x500.sdf` sử dụng model `x500` nguyên bản.
**Sau khi cập nhật:** Tạo thành công file `baylands_x500_mono_cam.sdf`. File này đã được chỉnh sửa phần `<world name='baylands_x500_mono_cam'>` và thẻ include để nạp `<uri>model://x500_mono_cam</uri>`.

### 2. Cập nhật `scripts/run_gazebo_sim.sh`
**Trước khi cập nhật:** Script dùng cấu trúc `case` chỉ hỗ trợ cờ `--baylands_x500` và `--aruco_x500`. 
**Sau khi cập nhật:** Thêm nhánh `case` cho cờ `--baylands_x500_mono_cam` gán biến `world="baylands_x500_mono_cam"`, đồng thời cập nhật dòng echo `Usage`.

### 3. Cập nhật `scripts/run_px4_autopilot.sh`
**Trước khi cập nhật:** Script gán cứng `PX4_GZ_MODEL_NAME=x500` ở cuối file.
**Sau khi cập nhật:** 
- Thêm biến mặc định `model="x500"`.
- Bổ sung `case` `--baylands_x500_mono_cam` và cấu hình override `model="x500_mono_cam"`.
- Tại lệnh chạy PX4 cuối file, `PX4_GZ_MODEL_NAME` được truyền bằng biến `"$model"`.

### 4. Cập nhật `README.md`
**Trước khi cập nhật:** Tài liệu ở phần *How to Run the Simulation* chỉ hướng dẫn 2 tham số.
**Sau khi cập nhật:** Bổ sung thêm dòng `# OR (with FPV camera)` và lệnh `--baylands_x500_mono_cam` vào cả phần chạy Gazebo và chạy PX4.

## III. Hướng dẫn sử dụng hiện tại
Bạn đã có thể gọi trực tiếp:
- Terminal 1: `uav_gzb --baylands_x500_mono_cam`
- Terminal 2: `uav_px4 --baylands_x500_mono_cam`

## IV. Xử lý lỗi (Troubleshooting) - Lỗi thiếu Symlink file SDF
**Mô tả lỗi:** Sau khi tạo file `baylands_x500_mono_cam.sdf` và gõ lệnh `uav_gzb --baylands_x500_mono_cam`, Gazebo không load được world.
**Nguyên nhân:** Script `simulation-gazebo` của PX4 tự động quét world trong thư mục `~/.simulation-gazebo/worlds/`. Do file world mới được tạo nằm trong `~/dariusuav/gazebosim/custom_world/` nhưng chưa được tạo Symlink (lối tắt) sang thư mục gốc của hệ thống nên Gazebo không tìm thấy. Lệnh quét ký tự đại diện `*.sdf` trong quá khứ chỉ tạo liên kết cho các file tồn tại vào thời điểm đó, không áp dụng cho file mới.
**Cách khắc phục:** 
Đã chạy lệnh sau để vượt qua sandbox và cập nhật lại các symlink:
```bash
mkdir -p ~/.simulation-gazebo/worlds && ln -sf ~/dariusuav/gazebosim/custom_world/*.sdf ~/.simulation-gazebo/worlds/
```
**Bài học kinh nghiệm:** Mỗi khi tạo một file world (`.sdf`) hoàn toàn mới, cần phải chạy lại câu lệnh symlink trên để Gazebo có thể nhận diện được file mới. Việc chỉ chỉnh sửa file đã tồn tại thì không cần phải chạy lại lệnh này.

## V. Xử lý lỗi (Troubleshooting) - PX4 Timeout (Lỗi cấu hình Model Name & Autostart)
**Mô tả lỗi:** Lệnh `uav_px4 --baylands_x500_mono_cam` bị treo ở bước `INFO [init] Waiting for Gazebo world...` và cuối cùng báo lỗi `ERROR [init] Timed out waiting for Gazebo world` mặc dù Gazebo ở Terminal 1 đã chạy.
**Nguyên nhân gốc rễ:** 
1. Mặc dù file `baylands_x500_mono_cam.sdf` đã chèn `model://x500_mono_cam`, nhưng thẻ `<name>` (alias trong Gazebo) vẫn là `x500`. Do đó, khi PX4 sử dụng biến `PX4_GZ_MODEL_NAME=x500_mono_cam` để tìm kiếm model trong Gazebo, nó không tìm thấy dẫn tới bị timeout.
2. Script chạy PX4 dùng chung thông số điều khiển (Airframe autostart ID) là `4001` (dành cho Quadcopter cơ bản), trong khi model camera `x500_mono_cam` cần khởi động đúng ID là `4010` để load chính xác các parameter.
**Cách khắc phục:**
1. Mở file `baylands_x500_mono_cam.sdf`, đổi thẻ `<name>x500</name>` thành `<name>x500_mono_cam</name>`.
2. Mở file `scripts/run_px4_autopilot.sh`, bổ sung biến `autostart` và cấu hình riêng cho cờ `--baylands_x500_mono_cam` sử dụng `autostart="4010"`. Gán động biến này vào tham số `PX4_SYS_AUTOSTART="$autostart"` khi gọi `px4`.
**Bài học kinh nghiệm:** Luôn đảm bảo tên thẻ `<name>` bên trong file world SDF trùng khớp hoàn toàn với tên truyền vào cho biến `PX4_GZ_MODEL_NAME`. Ngoài ra, cần đối chiếu với thư mục `ROMFS/px4fmu_common/init.d-posix/airframes/` để truyền đúng ID `SYS_AUTOSTART` tương ứng với model máy bay.

## VI. Xử lý lỗi (Troubleshooting) - PX4 Mất kết nối cảm biến (Lỗi parse SDF merge='true')
**Mô tả lỗi:** Sau khi khắc phục lỗi ở mục V, PX4 đã kết nối được với Gazebo nhưng văng lỗi `Preflight Fail: Accel Sensor 0 missing`, `barometer 0 missing`, `Gyro Sensor 0 missing`. Máy bay không thể cất cánh.
**Nguyên nhân gốc rễ:**
Trình phân tích (parser) SDF của module `gz_bridge` trong PX4 hiện tại chưa hỗ trợ thẻ `<include merge='true'>`. Trong khi đó, file `x500_mono_cam/model.sdf` lại sử dụng thẻ này để kế thừa bộ cảm biến IMU từ model `x500` gốc. Vì PX4 parser không đọc được, nó kết luận máy bay "không có cảm biến".
**Cách khắc phục:**
Chúng ta phải "đánh lừa" PX4 bằng cách ép cầu nối `gz_bridge` sử dụng file cấu hình của model gốc (`x500`):
1. **Trong `baylands_x500_mono_cam.sdf`:** Trả lại thẻ định danh về `<name>x500</name>` (vẫn giữ `<uri>model://x500_mono_cam</uri>` để hiển thị camera 3D).
2. **Trong `scripts/run_px4_autopilot.sh`:** Trả lại biến `model="x500"` và `autostart="4001"` cho cờ `--baylands_x500_mono_cam`.
**Bài học kinh nghiệm:** Việc đánh lừa alias này là một mẹo rất quan trọng trong hệ sinh thái PX4 Gazebo. Nó giúp PX4 quét đúng thông số vật lý/cảm biến chuẩn của model gốc (để bay), trong khi Gazebo vẫn render được các chi tiết đồ họa/sensor bổ sung (như camera).

## VIII. Các lệnh xem Camera Image (ROS2 & RViz/rqt)
**Mô tả:** Các lệnh dưới đây được sử dụng để kiểm tra, làm cầu nối và trực quan hóa luồng hình ảnh (image) xuất ra từ camera trong Gazebo sang hệ sinh thái ROS2.

### 1. Kiểm tra topic hình ảnh trên Gazebo
```bash
gz topic -l | grep image
```
**Mục đích:** Liệt kê tất cả các topic trong Gazebo và lọc ra topic chứa từ khóa `image`. Giúp xác nhận camera trong Gazebo đang hoạt động và lấy tên topic chính xác.

### 2. Cầu nối (Bridge) hình ảnh từ Gazebo sang ROS2
```bash
ros2 run ros_gz_bridge parameter_bridge '/world/baylands_x500_mono_cam/model/x500/link/camera_link/sensor/camera/image@sensor_msgs/msg/Image[gz.msgs.Image'
```
**Mục đích:** Tạo node `parameter_bridge` của gói `ros_gz_bridge`. Lệnh này nhận luồng hình ảnh từ Gazebo (kiểu dữ liệu `gz.msgs.Image`) và chuyển đổi, phát (publish) sang hệ sinh thái ROS2 (kiểu dữ liệu `sensor_msgs/msg/Image`). Lệnh này cần được giữ chạy liên tục trên một terminal riêng.

### 3. Xem hình ảnh trên ROS2
Sau khi đã bridge, bạn có thể xem hình ảnh bằng một trong hai công cụ sau (mở trên terminal mới):

**Cách A: Bằng RViz2**
```bash
rviz2
```
**Cách dùng:** Trong cửa sổ RViz2 -> Nhấn **Add** (góc dưới bên trái) -> Chọn display **Image** -> Trong bảng Displays, ở mục Image vừa thêm, cấu hình trường **Topic** trỏ tới topic của bridge để xem hình ảnh.

**Cách B: Bằng rqt_image_view (Nhẹ và nhanh hơn)**
```bash
ros2 run rqt_image_view rqt_image_view
```
**Cách dùng:** Mở giao diện của công cụ `rqt_image_view`. Trên thanh menu thả xuống (dropdown box) ở phía trên cùng, hãy chọn topic hình ảnh tương ứng để xem trực tiếp video luồng.

### 4. Kiểm tra kết nối đồ thị ROS2
```bash
rqt_graph
```
**Mục đích:** Hiển thị sơ đồ trực quan các node và topic đang chạy trong ROS2. Lệnh này hữu ích để gỡ lỗi (debug) và kiểm tra xem bridge node có đang kết nối và trao đổi dữ liệu với các hiển thị (RViz/rqt) đúng cách hay không.
